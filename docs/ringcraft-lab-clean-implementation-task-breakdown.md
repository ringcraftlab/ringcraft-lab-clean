# ringcraft-lab-clean 実装タスク分解（設計準拠）

本ドキュメントは `docs/ringcraft-lab-clean-design-guidelines.md` を実装に落とすための作業分解である。  
**実装順序・完了条件・レビュー観点**を明示し、差戻しを減らすことを目的とする。

---

## 0. 運用ルール（着手前）

- [ ] 変更対象ファイルをタスクごとに宣言する（無関係ファイルを触らない）
- [ ] ブレークポイント値（900/1024）を追加・変更する場合は定義元を統一する
- [ ] UI調整は「値の個別変更」ではなく「セット（幅/余白/比率/挙動）」で行う
- [ ] 1タスク完了ごとにスクリーン確認（PC幅 / 1024近辺 / 900以下）

---

## 1. ブレークポイント統一タスク

## 1-1. 目的

- 900px と 1024px の役割分離をコード上で明確化する

## 1-2. 作業

- [ ] 900px（操作判定）を使う箇所を抽出し、命名を統一する（例: `isNarrowInteraction`）
- [ ] 1024px（骨格判定）を使う箇所を抽出し、命名を統一する（例: `isStackedLayout`）
- [ ] Step4 内で 768px など別閾値が残っている場合は、採用方針に沿って統合する
- [ ] CSSメディアクエリの 1024px 適用範囲を確認し、JS判定と責務衝突がない状態にする

## 1-3. 完了条件

- [ ] 操作判定は 900px 系、骨格判定は 1024px 系に分離されている
- [ ] 例外閾値を使う場合、理由がコメントまたは設計メモで説明されている

---

## 2. Step1〜3 レイアウト整理タスク

## 2-1. 目的

- Step1〜3 を「同一構造を縮める」方針で統一し、Step4の複雑分岐を持ち込まない

## 2-2. 作業

- [ ] Step1〜3 のコンテナ上限幅・余白ルールを統一する
- [ ] モバイル時のCTA到達性（下部配置/余白）を再確認する
- [ ] 各Stepでカード密度（余白・行間）が一貫しているか確認する

## 2-3. 完了条件

- [ ] Step1〜3 でレイアウト思想が一致（中央寄せPC、縦積みモバイル）
- [ ] 900px 以下で主要操作が画面内で迷わず見つかる

---

## 3. Step4 骨格レイアウトタスク（1024px基準）

## 3-1. 目的

- Step4 を PC 2ペイン / 1024以下 1カラムの骨格に固定する

## 3-2. 作業

- [ ] 1025px以上: 左操作 + 右プレビュー列の2ペインを実装確認
- [ ] 1024px以下: 縦積み1カラムへ切替を実装確認
- [ ] `aside` / `main` の表示切替を CSS主体で制御する
- [ ] 右固定編集パネル表示時の右余白計算をメイン列に連動させる

## 3-3. 完了条件

- [ ] 1024px境界で骨格が意図どおりに切り替わる
- [ ] 編集表示時もプレビュー列が潰れない（右余白連動）

---

## 4. Step4 編集モーダルタスク（900px基準）

## 4-1. 目的

- PC とモバイルで編集体験を分離し、旧リポ方針に揃える

## 4-2. 作業（PC）

- [ ] 900px超では右固定編集パネルを表示（scrimなし）
- [ ] パネル開閉時に背景プレビュー確認を阻害しない
- [ ] z-index とヘッダー重なりを固定化

## 4-3. 作業（モバイル）

- [ ] 900px以下では bottom sheet を表示
- [ ] scrim表示・閉じる導線（閉じるボタン/背面）を統一
- [ ] `max-height` + 内部スクロールを有効化

## 4-4. プレビュー作業

- [ ] `previewW/previewH` を props 経由で渡す
- [ ] cap付き `calcPreviewSize`（px固定）を適用
- [ ] `object-fit`（cover/contain/fill）と回転挙動を確認

## 4-5. 完了条件

- [ ] PCは固定パネル、モバイルはシートに明確分離
- [ ] 画像比率が変わってもプレビュー破綻（極小/極大）がない

---

## 5. CSS / JS 責務分離タスク

## 5-1. 目的

- 見た目崩れの再発を防ぐため、責務の混線を解消する

## 5-2. 作業

- [ ] 骨格（grid/flex/表示切替）を CSS 側へ寄せる
- [ ] JS からは状態・操作・計算（preview size）のみ扱う
- [ ] コンポーネント内 `sx`/inline style を棚卸しし、骨格指定を減らす
- [ ] 同一責務の重複（CSSとJSの二重指定）を解消する

## 5-3. 完了条件

- [ ] CSSを見ればレイアウト骨格が追える
- [ ] JSを見れば状態遷移・操作だけが追える

---

## 6. 画面確認マトリクス（必須）

- [ ] PC大画面（>1280）
- [ ] PC標準（1100〜1280）
- [ ] 境界上（1024）
- [ ] 中間（901〜1024）
- [ ] 境界下（900）
- [ ] スマホ（<=430）

各幅で以下を確認：

- [ ] Step4 骨格（2ペイン/1カラム）
- [ ] 編集UIの表示方式（固定パネル/ボトムシート）
- [ ] プレビュー比率追従（cover/contain/fill + rotation）
- [ ] 横スクロール発生なし

---

## 7. レビュー観点（PR前）

- [ ] ブレークポイント役割が混ざっていない（900=操作、1024=骨格）
- [ ] Step4EditModal の仕様が PC/モバイルで意図どおり分離
- [ ] プレビュー計算ロジックにハードコードの破綻値がない
- [ ] 余白連動（右固定パネル時）が機能している
- [ ] 追加変更が設計ドキュメントと矛盾していない

---

## 8. 実装順序（推奨）

1. ブレークポイント統一（Task 1）  
2. Step4骨格レイアウト（Task 3）  
3. Step4編集モーダル（Task 4）  
4. CSS/JS責務分離（Task 5）  
5. Step1〜3整合（Task 2）  
6. 画面確認マトリクス + 最終レビュー（Task 6/7）

この順で進めると、Step4の揺れを先に止めてから周辺画面へ波及できる。
